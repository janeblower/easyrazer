# Прошивка аналоговой линейки Huntsman V3

Разбор официального Firmware Updater `v1.03.00_r1` (прошивка `1.03.00`, та же,
что Synapse называет `1.3.0.0`). Это справка для протокола: код прошивки в
проект не переносим. Адреса указаны для этой версии. Выводы без прямой проверки
помечены «вероятно». Команды — в [protocol.md](protocol.md).

## Образ

Updater тот же, что у V2 (.NET, распаковывается 7-Zip), параметры в
`DeviceUpdater.resources`:

| Ключ | Значение |
|---|---|
| `VID` / `PID` | `1532` / `02A6` |
| `BLPID` / `BLVER` | `110E` / `2.0` — загрузчик, как у V2 |
| `DevFWVer` / `FlashFWVer` | `1.03.00` / `1.03.00` |
| `FeatureReportLen` | `91` |
| `RYFWFileName` | `Talia_T1_7203_App_FW_20240426_v1.3.0_0D55D9FF.enc` |

Образов два:

- `DevFWLine0..8292` — Intel HEX главного MCU, открытый: `0x20000000`–`0x200205FF`,
  132 608 байт.
- `FlashFWSector0..36` — 37 408 байт, зашифрованы (энтропия ~6.2 бит/байт),
  прошиваются через `Ry_Online_Update_Dll`. Вероятно, это второй чип; для
  протокола не понадобился. `update/update_config.ini` ссылается на PID `02B0` и
  другой `.enc` — похоже, остался от V3 Pro Mini.

Разбор в Ghidra 12 headless: `ARM:LE:32:Cortex`, raw binary с базой
`0x20000000`, плюс неинициализированные блоки SRAMX `0x04000000`, RAM
`0x20020600`, периферии `0x40000000` и SCS `0xE0000000`.

## Микроконтроллер

NXP LPC55xx, Cortex-M33; вероятно, LPC55S6x с 640 КБ flash:

- строки NXP MCUXpresso SDK 2.8.2 (`fsl_gpio.c`, `fsl_spi.h`, `fsl_utick.c`),
  девять FLEXCOMM, CTIMER, UTICK, WWDT, GINT;
- старт пишет `MSPLIM` — регистр есть только в ARMv8-M;
- страница flash — 512 байт; прошивка использует flash до `0x87FFF`, это больше
  512 КБ;
- стек — `0x04008000`, конец 32 КБ SRAMX;
- код слинкован в RAM, а не во flash: его, вероятно, копирует туда загрузчик.

## Запуск

- Reset (`0x20000214`) → `MSPLIM = 0x04006000` → `SystemInit` (`0x20004084`) →
  `__main` (`0x20000200`): стек, scatter-load (`0x20000544`) → `main`
  (`0x2000EF3C`).
- Таблица scatter-load — `0x2001E958`, 4 записи `{src, dst, size, handler}`:
  `0x2001EA00` → `0x20020800` (`0x5C00`) и `0x2001FE00` → `0x04000000` (`0xA00`)
  распаковываются, `0x20026400` (`0x74A4`) и `0x04000A00` (`0x27D0`) обнуляются.
- Распаковщик `0x20000568` — LZ Keil. Токен `t`, затем:
  - `n = t & 3`, при `0` — следующий байт; дальше `n − 1` литералов;
  - `len = t >> 4`, при `0` — следующий байт (он стоит до литералов); `len = 0` —
    совпадения нет;
  - смещение назад — следующий байт плюс `(t & 0x0C) << 6`, а при
    `t & 0x0C = 0x0C` — вместо этого плюс ещё один байт `<< 8`; копируется `len + 2` байта.

После распаковки видны USB-дескрипторы, указатель на профили и прочие данные,
которых нет в образе в открытом виде.

## USB

Device-дескриптор — `0x20026040`, конфигурация — `0x20025F80`, 6 HID-интерфейсов;
таблица дескрипторов отчётов — `0x2001B340`.

| Интерфейс | EP | Дескриптор | Что |
|---|---|---|---|
| 0 | `81`, 8 | `0x200260C0` | boot-клавиатура |
| 1 | `82`, 48 | `0x04000740` | ID `01` NKRO, `02` consumer, `03` system control, `04` `05` `07` `0B` — vendor по 47 байт |
| 2 | `83`, 8 | `0x20026140` | мышь: 5 кнопок, колесо, X/Y по 16 бит |
| 3 | `03` out | `0x04000540` | управление: feature 90 байт без ID |
| 4 | `84`, 2 | `0x040005C0` | HID LampArray, feature ID `01`–`06` |
| 5 | `85` / `05`, 64 | `0x04000880` | vendor, 64 байта в обе стороны, назначение не выяснено |

В отличие от V2, на интерфейсе 0 нет коллекций геймпада и consumer.

## Профили

Профиль — `0x11B3` байт. Профиль 0 (рабочая копия) — в RAM, `0x200269A8`.
Профили 1–6 — во flash, `0x49E00 + n·0x11B3`: команды читают и пишут их прямо
там (см. [«Запись во flash»](#запись-во-flash)). Номер больше 6 команды
отвергают. Активный профиль — `0x20029002` (settings `+2`).

| Смещение | Поле |
|---|---|
| `+0x979` | уровень актуации (см. ниже) |
| `+0x980` | пороги: 135 × 7 байт `fwID ? ? H:u16 L:u16` (LE в памяти) |
| `+0xD31` | RT включён |
| `+0xD32` | уровень RT |
| `+0xD33` | RT: 135 × 8 байт `fwID on on up:u16 down:u16 01` |
| `+0x116B` | continuous RT (`02:20`) |
| `+0x116C` | Snap Tap: `on fwID1 fwID2` (`02:21`) |
| `+0x116F` | флаг `02:07` |
| `+0x1172` | 4 байта `02:15` |
| `+0x11B1` | CRC-16/CCITT-FALSE (init `FFFF`, полином `1021`) по `+0`…`+0x11B0` |

Рабочие копии таблиц для текущего профиля: пороги — `0x20027328`, уровень —
`0x20027321`; RT — `0x200276DB`, флаг — `0x200276D9`, уровень — `0x200276DA`;
continuous RT — `0x20027B13`; Snap Tap — `0x20027B14`–`0x20027B16`. Режим
устройства (`00:04`) — `0x04000DE3`.

## Карта flash

| Адрес | Что там |
|---|---|
| `0x49000` | config, `0x425` байт; в RAM — `0x04002000`, серийник на `+6` (`00:82`) |
| `0x49C00` | settings, `0x177` байт; в RAM — `0x20029000`: `+2` активный профиль, `+5`–`+0x12` — вероятно, индекс макросов |
| `0x49E00` | профили 1–6 по `0x11B3` байт |
| `0x53600` | 16 байт, в RAM — `0x04000DA4` |
| `0x53800`–`0x543FF` | заводская область: её читает команда `81` обработчика прочих классов по 32-битному смещению |
| `0x54400`–`0x7F3FF` | вероятно, хранилище макросов: проигрыватель читает отсюда события по 5 байт |

Сброс (`0x2001A898`) стирает `0x49C00`–`0x87FFF`: settings, профили, макросы и
то, что дальше. Config не трогает.

## Запись во flash

- `0x2000C430(addr, src, n)` — запись диапазона: страница 512 байт читается в
  `0x04001000`, меняется и перепрограммируется (`0x2000C39C`), до 3 повторов.
  Страница 512 байт — ещё один довод за LPC55xx.
- `0x2001A074` пересчитывает CRC профиля и пишет её той же функцией.
- Отложенного сохранения, как у V2, нет: команда в профиль 1–6 (`02:19`, `02:1A`,
  `02:20`, `02:21`, `02:07`, `02:15`) сразу стирает минимум две страницы —
  данные и CRC. Пачка на 15 клавиш стоит столько же, сколько одна клавиша, так
  что писать во flash надо крупными пачками, а живые изменения — в профиль 0.
- Профиль 0 остаётся в RAM: `02:12` идёт в `0x20019BA0`, `02:1A` — в `0x20019B24`
  с флагом «не сохранять», `02:21` пишет прямо в `0x20027B14`; ни одна из них не
  вызывает `0x2000C430`. Живые изменения работают как на V2.
- Конфиг и настройки сохраняются с задержкой, как профили V2: `0x200161E8` ставит
  бит в `0x2002AF28` (`1` — настройки, `2` — конфиг) и счётчик `0x67` в
  `0x2002AF2A`; `0x200151C4` пишет страницу, когда он истечёт.

## Смена режима

`00:04` (`0x2001189C`): при переходе из другого режима в `03`, если активен не
профиль 1, прошивка делает активным профиль 1 (`0x20029002 = 1`) и помечает
настройки к сохранению — через `0x67` тиков стирается `0x49C00`. Когда профиль 1
уже активен, переключения ничего не пишут; выход из driver mode старый профиль не
возвращает. Значит, профиль, с которым клавиатура стартует без программы, молча
становится первым, а программа, которая ставит другой стартовый слот и снова входит
в driver mode, платит за это стиранием каждый раз. Режим `01` только ставит
`0x2002686D` (вероятно, запрос перезагрузки в загрузчик).

## Матрица клавиш

- Матрица датчиков — 8 × 14 (`0x2001D1D0`, fwID по позиции), 111 клавиш и одна
  пустая ячейка. Позиция кодируется байтом: столбец — старшие 4 бита, строка + 1 —
  младшие. Состояние клавиши — 6 байт, `0x04001288 + строка·0x54 + столбец·6`.
- Набор fwID тот же, что в матрице V2, кроме `152` / `153` (Hanja / Hangeul):
  имена клавиш из `crates/core/src/keymap.rs` подходят.
- Подсветка — 6 × 22 (`0F:03` принимает строки 0–5 и столбцы 0–21), буфер
  кадра — `0x20028C74`, 66 байт на строку. У V2 — 8 × 22.

## Срабатывание

- Пороги и RT — u16, 1638 = 0.1 мм. Таблица уровней актуации `0x2001B3DE`:
  `1638·{1, 4, 8, 12, …, 36}` (0.1, 0.4, 0.8 … 3.6 мм); RT — `0x2001E11E`:
  `1638·{1…10}` (0.1…1.0 мм).
- При записи всех клавиш (`fwID = FF`) прошивка ставит «уровень» профиля —
  наибольший номер ступени, не превышающий L первой клавиши (для RT — down).
  Зачем он, не выяснено; вероятно, для индикации.
- Старые `02:12` / `02:92` работают со старшим байтом u16.
- Driver mode (`03`), `0x20007BC4`: глубина каждой клавиши отображается в
  `0..0xFFFF`, меньше `0x666` (0.1 мм) считается нулём. Изменившиеся клавиши
  копятся в отчёте `0B` (`0x20027D88`): до 15 записей `fwID depth:u16` (BE),
  отпущенная клавиша из него убирается. Отправка — интерфейс 1, 48 байт.

## Snap Tap

Обработка события клавиши (`0x2000DA74`, перед движком нажатий): если `02:21`
включён и режим не `03`, нажатие клавиши пары отпускает вторую, отпускание —
снова нажимает вторую, если она удерживается. Состояние пары — `0x200283CC`–
`0x200283CE` и `0x040019C8`–`0x040019CA`.

## Не разобрано

- Перезагружается ли профиль 0 из профиля 1, когда driver mode делает его активным,
  и при возврате в hardware mode.

- Формат config, settings и макросов; ресурс страницы flash.
- Опрос датчиков, калибровка и решение о нажатии.
- Отчёты `04`, `05`, `07` интерфейса 1 и интерфейс 5.
- Байты `+1`, `+2` записи порогов, эффект `0A`, флаг `02:1F`.
- Второй образ (`.enc`).

- Диспетчер классов и набор команд: считаем таким же, как у V3 Pro, по Synapse.
- Подсветка: таблица fwID из 6 строк по `0x2001D6E9` — вероятно, матрица подсветки.
