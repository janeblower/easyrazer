# Прошивка Huntsman V2 Analog

Разбор официального Firmware Updater `v1.06.00` (прошивка `1.06.00`). Это справка
для протокола: код прошивки в проект не переносим. Адреса указаны для этой версии.
Выводы без прямой проверки помечены «вероятно». Команды канала управления описаны в
[protocol.md](protocol.md).

## Образ

Updater — .NET-программа. Образ лежит в `DeviceUpdater.resources` (exe распаковывается
7-Zip): строки `DevFWLine0..N` — записи Intel HEX по порядку номеров. Там же
параметры:

| Ключ | Значение |
|---|---|
| `VID` / `PID` | `1532` / `0266` |
| `BLPID` / `BLVER` | `110E` / `2.0` — загрузчик |
| `DevFWVer` / `FlashFWVer` | `1.06.00` / `1.02.00` |
| `FeatureReportLen` | `91` |

Образ не зашифрован: `0x08007000`–`0x0801D043`, 90 180 байт. Сжата только секция
инициализированных данных (см. [«Запуск»](#запуск)).

Разбор делался в Ghidra 12 headless: `ARM:LE:32:Cortex`, raw binary с базой
`0x08007000`, плюс неинициализированные блоки RAM `0x20000000`, периферии
`0x40000000` и данных flash `0x08080000`. Судя по коду старта, собрано компилятором Keil (ARM CC),
периферия — через ST HAL. У части функций декомпилятор выводит неверную сигнатуру
(CRC видна как `void`); такие места сверены с дизассемблером.

## Микроконтроллер

STM32L4+ с 1 МБ flash в двух банках и 320 КБ RAM, вероятно, STM32L4P5/L4Q5:

- ADC `0x50040000`, GPIO `0x48000000`, DMAMUX `0x40020800`, UID `0x1FFF7590`,
  USB OTG FS `0x50000000`;
- запись flash выбирает банк по биту DBANK в `FLASH_OPTR` и адресу `0x08080000`,
  страница — 4 КБ; так устроен только dual-bank режим L4+;
- метка загрузчика пишется в `0x2004FFFC`, последнее слово 320 КБ RAM.

## Запуск

- Reset (`0x080071D4`) → `SystemInit` (`0x0800D5D4`) → стек `0x2000EC68` →
  scatter-load (`0x0800725C`) → `main` (`0x08013CF4`).
- Scatter-load по таблице `0x0801CF7C` распаковывает `0x240` байт данных из
  `0x0801CF9C` в `0x20000000` (LZ-распаковщик Keil, `0x08007280`) и обнуляет
  `0x20000240`–`0x2000EC67`. Всего прошивка использует около 59 КБ RAM.
- `main`: инициализация периферии (в том числе I2C1 и I2C2 — `0x0800CDB0`,
  `0x0800CE0C`), загрузка config, settings, профилей и индекса макросов
  (`0x08012C94`), затем бесконечный цикл.
- Тактирует `0x0800E5CC` — вероятно, callback USB SOF (1 мс): раз в `settings+0x5F` кадров
  (интервал опроса, `00:05`) идут проигрыватель макросов, turbo и отправка отчётов.
  Задержки макросов считаются в этих интервалах.

## Карта flash

| Адрес | Что там |
|---|---|
| `0x08000000`–`0x08006FFF` | загрузчик (в образ не входит) |
| `0x08007000`–`0x0801D043` | прошивка |
| `0x0801A724` | версия прошивки, 4 байта |
| `0x0801A728` / `0x0801AD75` | заводские config / settings |
| `0x0801AF90` | комбинация клавиш для режима `0xAA` |
| `0x0801AFA0` | атрибуты LampArray |
| `0x0801BA00`, `0x0801BBA0` | таблицы «матрица ↔ fwID» |
| `0x0801BA80` | линии мультиплексора датчиков: 8 × {порт GPIO, пин} |
| `0x0801BCAE` | профиль по умолчанию, `0xA9D` байт (имя `default`) |
| `0x0801C74B` | назначения клавиш по умолчанию, `0x7E0` байт |
| `0x08080000` | config, `0x64D` байт |
| `0x08081000` | settings, `0x1E4` байт |
| `0x08088000`–`0x0808DFFF` | профили 1–6, по странице 4 КБ; командами доступны 1–5 |
| `0x08090000`–`0x080FFFFF` | хранилище макросов, `0x70000` байт |

Блоки config, settings и профилей устроены одинаково: первое слово — размер блока,
последние два байта — CRC-16/CCITT-FALSE (init `FFFF`, полином `1021`) по всему
остальному. При неверном размере или CRC прошивка берёт заводской блок и
записывает его.

## Config, settings, профиль

**Config** (`0x64D`): `+4`, `+5` — `00:06`; `+6` — серийник, 22 байта; калибровка
датчиков — 12 байт на клавишу (`row·0xC0 + col·0xC`), пара u16 в `+0x33` / `+0x37`;
`+0x62F`, `+0x63D` — блоки `00:3D`.

**Settings** (`0x1E4`):

| Смещение | Поле |
|---|---|
| `+2` | активный профиль |
| `+3` | задержка между событиями макроса (`06:07`) |
| `+4`, `+8`, `+0xC`, `+0x10` | индекс макросов: ёмкость, занято, адрес, CRC |
| `+0x1E` | 4 байта `02:02` |
| `+0x25` | эффект подсветки по умолчанию, 34 байта |
| `+0x5D` | `0xAA` — особый режим |
| `+0x5E` | `0F:10` |
| `+0x5F` | интервал опроса (`00:05`) |
| `+0x60` | по 3 байта на клавишу (`row·0x30 + col·3`); `02:13` пишет второй и третий |

**Профиль** (`0xA9D`):

| Смещение | Поле |
|---|---|
| `+0` | номер |
| `+2` | существует |
| `+6` | имя |
| `+0x104` | назначения слоя Normal: 126 × 8 байт `fwID fnId size data[5]` |
| `+0x4F4` | назначения слоя Hypershift, тот же формат |
| `+0x8E4` | пороги: 126 × 3 байта `fwID thrH thrL` |
| `+0xA5E` | флаг `02:07` |
| `+0xA5F` | флаг `0F:06` |
| `+0xA63` | эффект подсветки, 34 байта |

В driver mode при загрузке профиля назначения профиля 0 заменяются значениями по
умолчанию из `0x0801C74B`. Поэтому в этом режиме профиль 0 принимает только пороги.

## Запись во flash

- `0x08011D48` — запись произвольного диапазона: страница 4 КБ читается в
  `0x20007000`, меняется, стирается и программируется двойными словами, до 3
  повторов. Любая запись, даже 4 байта, стоит стирания страницы.
- Команды сами во flash не пишут: `0x08017724(n)` ставит бит в `0x200000F4` и таймер.

| n | Бит | Действие |
|---|---|---|
| 0 | `02` | config — сразу, без таймера |
| 1 | `01` | settings — после таймера (`0x67` тиков) |
| 4 | `08` | перезагрузка, когда остальное записано (`00:0B 00`) |
| 2, 5, 7 | `04`, `10`, `40` | в цикле сохранения не обрабатываются |

- Профили сохраняет `0x08016F48` по маске `0x2000017C`: через 100 тиков после
  последнего изменения, по одному профилю в 40 тиков.

## Датчики и срабатывание

- TIM2 (IRQ 28) → `0x08017D0C`: выбирает одну из 8 линий мультиплексора
  (`0x0801BA80`), читает два ADC по 8 каналов и кладёт 16 значений в строку
  `0x200058BC`. За 8 прерываний опрашиваются все 128 позиций.
- Когда все 8 линий прочитаны, TIM6 (IRQ 54) запускает обработку `0x0800F6E8`.
  Для каждой позиции глубина = `255 − map(raw)`, где `map` — линейное отображение по калибровке клавиши (`+4`/`+8` → `+0xC`/`+0x10` в
  состоянии клавиши).
- На железе (`FE:A7`, клавиша Q): покой ≈ `0x0E53`, до упора ≈ `0x0240`, калибровка
  `0x0448` / `0x0D0F`. Сырое значение ниже `0x0448` даёт глубину 255, выше `0x0D0F` —
  0; участок от покоя до `0x0D0F` — мёртвая зона в начале хода. Нажатая Q сдвигает
  соседний датчик A примерно на 10% хода.
- Пороги из профиля (`0x08017554`): нажатие = `thrL` в пределах `15..250`,
  отпускание = `thrH`, но не меньше `5` и не больше «нажатие − 10». Решение о
  нажатии — `0x08019274`.
- Driver mode (`03`): глубина — среднее 8 из 10 последних отсчётов без максимума и
  минимума (`0x08015A20`). В отчёт идут только изменившиеся клавиши, до 11 пар
  `fwID depth`.
- Режим `08` в коде — поток сырых значений или диапазонов калибровки выбранной
  группы клавиш. Номер группы (`0x200000EC`) нигде не записывается и всегда `0`,
  поэтому в этой версии поток не идёт.

## Движок нажатий

`0x08016148` получает событие клавиши и по fnId из назначения выполняет действие —
таблица в [protocol.md](protocol.md#срабатывание). Проверка fnId и длины данных —
`0x08012EBC`; её вызывают `02:0D` и `02:0F`, а `02:12` пишет назначение без проверки.

## Макросы

**Хранилище** — куча с граничными метками прямо во flash `0x08090000`–`0x080FFFFF`:

- в начале и в конце каждого блока — одно и то же слово `(size << 3) | free`,
  `size` включает 8 байт меток;
- выделение (`0x08011B08`) — первый подходящий свободный блок, размер округляется
  вверх до кратного 8, остаток блока отделяется в свободный;
- освобождение (`0x080119EC`) сливает блок с соседними свободными;
- пустое хранилище — один свободный блок `0x70000` (`0x080119B0`, он же форматирование
  `06:0A`);
- статистика `0x200001A8` (`всего, свободно, maxFree, …`) считается проходом по
  блокам при старте (`0x08018AB8`), в работе меняется только «свободно». `06:8E`
  отдаёт «всего» и `maxFree`, `06:86` проходит по блокам заново.

**Индекс** — массив записей по 14 байт в куче: `id32`, адрес блока метаданных
(`06:04` / `06:0C`), адрес тела (`06:08`), 2 байта. При первом старте — 100
записей (`0x578` байт), при переполнении индекс перевыделяется на 50 записей больше.
Отсюда `6FFF0` в «всего» на пустой клавиатуре: `0x578 + 0x6FA78`.

**Запись тела** (`0x08018FE0`): `06:09` копит подряд идущие куски одного макроса в
буфере `0x2000D6F0`, до 2 КБ. Во flash буфер уходит, когда кусок не продолжает
предыдущий, приходит другой id, буфер полон или 100 мс нет записи (`0x0800E5CC`).

**Проигрыватель** (`0x08013940`) — 20 слотов по 26 байт:

| Смещение | Поле |
|---|---|
| `+0` | активен |
| `+1` | клавиша |
| `+2` | режим |
| `+3` | счётчик |
| `+6` | задержка |
| `+0xA` | позиция |
| `+0xE` | текущее событие |
| `+0x12` | начало |
| `+0x16` | длина |

Событие читается прямо из flash, только если указатель внутри хранилища. Тела
макросов в RAM не копируются.

| Режим | fnId | Поведение |
|---|---|---|
| 1 | `03` | n проходов |
| 2 | `04` | по кругу; отпускание переводит в режим 1 со счётчиком 0 — доигрывается текущий проход |
| 3 | `05` | по кругу; повторное нажатие — как отпускание в режиме 2 |
| 4 | `0F` | каждое нажатие выставляет счётчик 2, каждое событие его уменьшает |

После каждого события задержка равна `settings+3` плюс задержки из событий `11`–`14`.

## Канал управления

- `SET_REPORT` (`0x21`/`09`) разбирает функция по адресу `0x0800DD3C`, данные
  приходят в `0x2000E7DC`:
  - Output-репорт — светодиоды Num/Caps/Scroll;
  - Feature на интерфейс 3 — пакет управления, принимается только при
    `wLength == 90` и свободном `0x2000011C`;
  - Feature на интерфейс 4 — LampArray.
- Пакет копируется в `0x20003690`, диспетчер (`0x08015568`) выполняется сразу, в
  прерывании USB, ответ копируется в `0x200036EC` для `GET_REPORT`.
- CRC запроса не проверяется, в ответ пишется XOR байтов 2..87. Во время обработки
  статус `01`, после — `02`; хост видит только `02`.

| Класс | Обработчик | Условие |
|---|---|---|
| `00` | `0x08014B8C` | — |
| `02` | `0x08014190` | — |
| `03` | `0x08014F84` | не в режиме `0xAA` |
| `05` | `0x08015620` | — |
| `06` | `0x08015178` | — |
| `0F` | `0x08014730` | не в режиме `0xAA` |
| `F0`, `FE` | `0x08015794` | только в режиме устройства `02` |

Неизвестная команда — статус `05`, ошибка аргументов — `03`.

## USB

- Конфигурационный дескриптор — `0x0801A69C`, 134 байта, 5 интерфейсов.
- HID report-дескрипторы — `0x0801A3B0`–`0x0801A52C`: мышь, consumer, vendor,
  клавиатура с report ID, NKRO, LampArray (`05 59`); геймпад среди них не найден.
- Строки: `Razer`, `Razer Huntsman V2 Analog`, `HID Config`, `HID Interface`.
- Feature-репорты LampArray (`0x080164B0`):
  - `1`–`3` — атрибуты; число ламп зависит от раскладки: 148, 149 или 153;
  - `4`, `5` — обновление ламп, переключает эффект на `08`, игнорируется при
    `0F:10 01`;
  - `6` — AutonomousMode; включение возвращает эффект из `settings+0x25`;
  - `7` — пакет управления, передаётся тому же диспетчеру.

## Подсветка

- Четыре драйвера на I2C: `0xA0`, `0xB8`, `0xBE` на I2C1, `0xA6` на I2C2 (адреса
  8-битные). На `0xA6` прошивка пишет только при низком уровне PB9 — вероятно,
  это подставка с датчиком подключения.
- Протокол записи: `0xFE` — разблокировка, `0xFD` — страница; страница 0 —
  вкл/выкл (24 байта), страница 1 — PWM (192 байта). Вероятно, это ISSI IS31FL3733
  или совместимый драйвер.

## Режимы устройства

| Режим | Поведение |
|---|---|
| `00` | hardware: клавиатура сама отправляет нажатия |
| `01` | запрет прерываний, `0xAAAAAAAA` в `0x2004FFFC`, `SYSRESETREQ`; клавиатура появляется как загрузчик `1532:110E`, вероятно, по этой метке |
| `02` | заводской: открывает классы `F0` / `FE` |
| `03` | driver: поток глубины, нажатия обрабатывает хост |
| `08` | код потока сырых значений есть, но в этой версии не работает |

**Режим `0xAA`** (`settings+0x5D`) переключается, если при подключении зажаты три
клавиши (`0x080116B0`, таблица `0x0801AF90`), и сохраняется в settings. По таблице
матрицы это, вероятно, Esc + Caps Lock + Space. В нём главный цикл идёт другой веткой, классы `03` и `0F`
игнорируются, подсветка — волна. Для чего он нужен, не выяснено. Та же
комбинация при следующем подключении выключает его.

## Не разобрано

- Загрузчик — в образ не входит.
- Точное назначение режима `0xAA`, полей `02:07`, `02:13`, `0F:06`, `00:06`,
  `00:3D` и fnId `06`, `08`.
- Device-дескриптор USB — вероятно, собирается в коде; не искался.
