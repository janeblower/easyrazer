# Протокол Huntsman V2 Analog

Всё проверено на живом устройстве (`1532:0266`, прошивка 1.1) или прочитано из кода
Synapse 4. Непроверенное помечено.

## HID-интерфейсы

| Интерфейс | Usage page / usage | Назначение |
|---|---|---|
| MI_00 | 0x01 / 0x06 | Обычная клавиатура (boot), ОС держит эксклюзивно |
| MI_00 Col02 | 0x01 / 0x04 | Геймпад-режим (out-репорт 521 байт) |
| MI_00 Col03 | 0x0C / 0x01 | Consumer / system control |
| MI_01 Col01 | 0x01 / 0x06 | NKRO-клавиатура |
| MI_01 Col04 | vendor | Razer-коды в driver mode: `04 <code>`, `04 00` — отпущено |
| MI_01 Col06 | vendor | Поток глубины в driver mode, report `07` |
| MI_02 | 0x01 / 0x02 | Мышь (макросы; колесо громкости в driver mode) |
| **MI_03** | 0x0C / 0x01 | **Управление**: feature report 91 байт |
| MI_04 Col01 | 0x59 / 0x01 | HID LampArray (Windows Dynamic Lighting) |

## Пакет управления (MI_03)

Report ID `00` + 90 байт. CRC входящего пакета прошивка не проверяет.


```
0      status: запрос 00; ответ 02 ok, 01 busy, 03 fail, 04 timeout, 05 not supported
1      transaction id (устройство принимает любой; используем 1F)
2-3    remaining packets
4      protocol type (0)
5      data size — фактическая длина payload
6      command class
7      command id; get = set | 0x80
8-87   args[80]
88     crc = XOR байтов 2..87
89     reserved
```

Обмен: `SetFeature` → пауза 5–20 мс → `GetFeature`, при busy — повтор.

## Режим и профили

- `00:84` / `00:04` — режим: `00` hardware (клавиатура печатает сама), `03` driver
  (обычные нажатия не шлются, шлётся поток глубины). После включения — `00`.
  ⚠️ `01` — устройство отваливается и перечисляется как `1532:110E`, лечится
  переподключением.
- `00:81` прошивка, `00:82` серийник.
- `05:84` активный профиль (`01`), `05:81` список (`01 01`), `05:8A` → `05` (максимум?).
- **Профиль 0 — рабочая копия в RAM**: при включении заполняется из сохранённого,
  запись в него не трогает flash, после переподключения теряется. Запись Normal в
  профиль 0 меняет и Hypershift в профиле 0; в профиле 1 слои раздельные.

## Актуация

Отдельных команд актуации и RT у V2 нет, порог живёт в назначении клавиши:

- `02:92` get `[profile, fwID, mode]` (mode 0 normal, 1 Hypershift), size 80.
- Ответ: `[profile, fwID, mode, thrL, thrH, fnId, fnSize, fnData…]`.
  Пример A: `01 1F 00 00 00 02 02 00 04` — fnId `02` клавиша, `00 04` модификатор + HID usage.
- `02:12` set — тот же формат. В профиле ≥1 пишет во flash.
- `мм = thr/255·2.1 + 1.5`. `0` — минимум 1.5 мм, а не «по умолчанию».
- `thrL` — точка нажатия. `thrH` влияет на отпускание (при `0/230` повтор гаснет
  почти у верха); **точная семантика не измерена**.
- Synapse пишет всем клавишам `0/0` и считает актуацию сам в driver mode.
- **В driver mode профиль 0 принимает только пороги**: смену fnId прошивка молча
  отбрасывает (ответ ok). В hardware mode в профиль 0 пишется всё.
- `02:0D` / `02:8D` — то же назначение без порогов: `[profile, fwID, mode, fnId,
  fnSize, fnData…]`.

fnId (из Synapse): `00` выкл, `02` клавиша, `03` макрос N раз (`id16, N`), `04` макрос
пока держишь (`id16`), `05` макрос до повторного нажатия (`id16`), `07` профиль,
`08` подсветка, `0A` media, `0D` turbo, `0F` макрос Sequence (`id16`). В профиль 0
проверены на запись `00`, `02`, `03`, `04`, `05`, `0A`, `0F`.

`fwID` — позиционные коды AT-101 (`~`=1, `Q`=17, `A`=31, Space=61), таблица —
`crates/core/src/keymap.rs`.

Не поддерживаются (`05`): `02:99`, `02:9A` (V3 multi-actuation и RT), `02:9F`,
`02:A0`, `02:A7`–`02:AA`. Для V3: `FW = мм·1638`, 16 бит BE.

## Поток глубины (driver mode)

- MI_01 Col06, report `07 (fwID depth)… 00`; пустой отчёт — всё отпущено.
- ~1 кГц, только при изменении, шум ±1–2.
- Глубина 0..255 = 1.5..3.6 мм — та же шкала, что у порога; 12 ед. = 0.1 мм.
- Нужен гистерезис отпускания ≥ 12 ед., иначе клавиша у порога дребезжит.
- `SendInput` не даёт автоповтора — хост повторяет сам.
- Fn-слой и медиа — на хосте: Col04 `04 52..55` — четыре медиа-клавиши, `04 01` — Fn.
- Колесо громкости приходит как колесо мыши (MI_02). Synapse ремапит его в
  VolumeUp/Down, видимо, своим фильтр-драйвером.
- `02:2A` (report mode) — not supported; в hardware mode поток не идёт.

Synapse на V2 делает RT и Snap Tap так же: `profile.appEngine = {mappings,
actuations[{keyId, make, break}], rapidTriggers{fwID: {makeSensitivity,
breakSensitivity}}}` отдаётся в `mapping_engine.dll` (report `07`, `SendInput`,
опционально фильтр-драйвер). Аппаратного RT нет.

## Подсветка

### Эффекты `0F:02`

Аргументы `profile led effect…`, `led` = `05`. `profile` `00` — рабочая копия в RAM,
`01`–`05` — профиль во flash (после переподключения возвращается эффект активного
профиля). Чтение `0F:82 profile 05`.

| Эффект | Байты после `profile 05` |
|---|---|
| выключено | `00 00 00 00` |
| статичный | `01 00 00 01 RGB` |
| дыхание 1 / 2 / случайное | `02 01 00 01 RGB` / `02 02 00 02 RGB RGB` / `02 00 00 00` |
| спектр | `03 00 00 00` |
| волна | `04 dir speed 00`, dir `01`/`02`, speed меньше — быстрее |
| отклик клавиша | `05 00 speed 01 RGB` (скорость не работает) |
| отклик рябь | `06 00 speed 01 RGB` |
| звёздное небо | `07 00 speed 00` / `… 01 RGB` / `… 02 RGB RGB`, speed 1–3 |
| своя раскладка | `08 00 00 00` |

Яркость — `0F:04 profile 05 VV`, чтение `0F:84`. Два цвета у отклика не работают.

### Своя раскладка `0F:03`

- `store 00 row start stop RGB×n`, size `5+3n`; сетка 8×23 (ряды 0–7, столбцы 0–22).
  Показ — `0F:02 00 05 08 00 00 00`.
- **Только во временной памяти**: эффект `08` в профиль ≥ `01` прошивка не сохраняет,
  хотя отвечает ok.
- Ряд 0 — F-ряд (медиа-кнопки — одна ячейка 18, колёсико — 21), 1–5 — клавиши,
  6 — огранка корпуса, 7 — подставка. Столбцы клавиш — `crates/core/src/layout.rs`.

### LampArray и Dynamic Lighting

- MI_04 Col01: 148 ламп (107 клавиш, 40 accent, 1 логотип), 30 кадров/с.
  Feature-репорты: `1` атрибуты, `2`/`3` лампа, `4` multi-update, `5` range-update,
  `6` AutonomousMode.
- **`AutonomousMode = 0`** — лампами управляет хост, `0F:02` не пробивается.
  `0 → 1` включает заводское переливание, а не записанный эффект — эффект надо
  отправить заново.
- DL со статичным цветом пишет один раз; с анимацией шлёт кадры непрерывно.
- Включение DL: `HKCU\Software\Microsoft\Lighting\AmbientLightingEnabled` (DWORD),
  служба применяет изменение сразу.

## Макросы

Тело макроса лежит в общем хранилище под своим id и не связано с клавишами;
клавиша ссылается на него назначением `02:12` с fnId `03`–`05`, `0F`. Прошивка
проигрывает макрос только в hardware mode.

- `06:08` `id16 size32` — выделить место. `06:09` `id16 offset32 len data…` —
  данные, до 72 байт за пакет. Читается `06:89` тем же форматом. Имя (`06:0D`)
  не нужно.
- **Тело пишется сразу во flash**, временного варианта нет. Временной может быть
  только привязка (профиль 0). Хранилище — встроенная flash `0x08090000`–`0x080FFFFF`;
  прошивка читает события прямо оттуда при проигрывании и только из этого
  диапазона ([firmware.md](firmware.md)).
- `06:80` количество, `06:81` / `06:8B` список id, `06:88 id16` размер, `06:03 id16`
  удалить.
- `06:8E` память: `maxId16, всего32, свободно32, recyclable32` (recyclable всегда
  0). На пустой клавиатуре всего `6FFF0`, свободно `6FA78` (457 336 байт).
- Макрос из `d` байт занимает `8 + ceil8(d + 6)`: 8 байт индекса уходят и из
  «всего», тело с 6-байтным заголовком — из «свободно». Проверено на
  d = 2, 3, 12, 73.
- **Счётчики `06:8E` пересчитываются только при подключении**: запись и удаление
  до переподключения их не меняют. Удаление место возвращает.
- `06:0A` (проверка и форматирование памяти в Synapse) отвечает `05`. По прошивке
  `05` здесь означает и ошибку аргументов, так что команда может существовать.

События, 2–5 байт:

| Байты | Событие |
|---|---|
| `01 usage` / `02 usage` | клавиша нажата / отпущена (HID usage) |
| `03`/`04`, `05`/`06` | power / media нажата / отпущена |
| `08 mask` | кнопки мыши |
| `0A 01` / `0A FF` | колесо вверх / вниз |
| `11 ms8`, `12 ms16`, `13 ms24`, `14 ms32` | задержка, BE |
| `15 x16 y16` | перемещение курсора |

Пример: `01 04 11 32 02 04 01 05 11 32 02 05` печатает `ab`.

## Команды по прошивке

Полный список из обработчиков прошивки 1.06 ([firmware.md](firmware.md)). Если не
сказано «проверено», на железе не проверялось. ⚠️ — пишет во flash то, что
Synapse не трогает; не отправлять.

### `00` — устройство

| cmd | Аргументы и смысл |
|---|---|
| `00:81` / `00:87` | версия прошивки, 2 / 4 байта (проверено `81`) |
| `00:02` / `00:82` | серийник, 22 байта; ⚠️ `02` перезаписывает его |
| `00:83` | всегда `00 60` |
| `00:04` / `00:84` | режим: `00` hardware, `02` заводской, `03` driver, `01` — перезагрузка в загрузчик (проверено `00`, `01`, `03`) |
| `00:05` / `00:85` | байт в settings, допустимо `1`–`5`, `8`, `10` — вероятно, частота опроса |
| `00:06` / `00:86` | два байта в config |
| `00:0B` | сброс: `00` — отложенная операция, `01 00` — settings к заводским, ⚠️ `01 01` — ещё и config (калибровка, серийник) |
| `00:3D` / `00:BD` | `idx(0/1)` + 14 байт в config |
| `00:B5 03` / `00:B9` | байт из `0x20000000` |

### `02` — клавиши

`profile` `00` — рабочая копия в RAM, `01`–`05` — flash; запись в активный
профиль копируется и в `00`.

| cmd | Аргументы |
|---|---|
| `02:02` / `02:82` | 4 байта в settings |
| `02:03` / `02:83` | `profile fwID fnId size data` — назначение без слоя |
| `02:0D` / `02:8D` | `profile fwID layer fnId size data` (проверено) |
| `02:12` / `02:92` | `profile fwID layer thrL thrH fnId size data` (проверено) |
| `02:11` / `02:91` | только пороги: `profile fwID _ thrL thrH` |
| `02:0F` | пакетно: `profile layer`, затем записи по 8 байт `fwID fnId size data[5]` |
| `02:8F` | `profile layer startFwID` → до 9 записей по 8 байт |
| `02:13` / `02:93` | `first last` + по 2 байта на клавишу, общие для всех профилей; смысл неизвестен |
| `02:07` / `02:87` | `profile flag` — флаг профиля, при смене сбрасывает нажатые клавиши; смысл неизвестен |

Длины данных для fnId — [firmware.md](firmware.md#назначения-клавиш).

### `03` — индикаторы

LED: `07` macro, `08` game (одноцветные), `18` RGB. Список — `03:89` → `03 07 01 08 01 18 03`.

| cmd | Аргументы |
|---|---|
| `03:00` / `03:80` | `00 led on` — вкл/выкл |
| `03:01` / `03:81` | `00 18 RGB` — цвет |
| `03:02` / `03:82` | `00 07 mode` (`0`/`1`) — вероятно, мигание |
| `03:04` / `03:84` | `00 07 on off` — длительности мигания, по 100 мс |

### `05` — профили

`05:80` количество, `05:81` список, `05:84` активный, `05:8A` → `05` максимум,
`05:02` создать, `05:03` удалить, `05:04 id` сделать активным, `05:08` / `05:88`
`id off16 total16 data` — блоб профиля (вероятно, имя и метаданные Synapse), `05:0B`.

### `06` — макросы

К описанному в «Макросах»: `06:02 id` — создать запись в индексе, `06:04` /
`06:84` `id n` + `n` слов, `06:07` / `06:87` — байт состояния хранилища,
`06:0A` / `06:8A` `id n …`, `06:0C` / `06:8C` `id off16 total16 data` —
блоб макроса (вероятно, имя), `06:8B off` — список id постранично. `06:85`,
`06:8D` → `05`.

### `0F` — подсветка

| cmd | Аргументы |
|---|---|
| `0F:80` | `05 19 03 0B 17` — возможности; `17` = 23 столбца |
| `0F:81` | `led` (`00`/`05`) → эффекты `01`–`08` |
| `0F:02` / `0F:82` | `profile led effect p1 p2 n RGB×n`, `n ≤ 10` (проверено) |
| `0F:03` | `profile row start stop RGB×n` (проверено) |
| `0F:04` / `0F:84` | `profile led VV` — яркость (проверено) |
| `0F:06` / `0F:86` | `profile flag` |
| `0F:10` / `0F:90` | байт в settings; `01` возвращает эффект из «своей раскладки» к сохранённому |

### `FE` / `F0` — заводской режим

Работают только в режиме устройства `02` (`00:04 02`), иначе `05`. `A7`, `A8`, `28`
требуют включённой калибровки (`FE:20 01`), иначе `03`.

| cmd | Аргументы |
|---|---|
| `FE:20` / `FE:A0` | включить / прочитать режим калибровки |
| `FE:A1` | `80`, если калибровка включена |
| `FE:A7` | записи `fwID 00 00` → сырое 16-битное значение датчика каждой клавиши, BE |
| `FE:A8` | записи `fwID` + 4 байта → пары калибровки (верх, низ), BE |
| `FE:28` | ⚠️ запись пар калибровки и сохранение во flash |
| `FE:83` | `ch < 8` — тест мультиплексора датчиков |

## Что ещё умеет Synapse для этой модели

По экранам Synapse 4 — ориентир для дорожной карты:

- **Срабатывание**: актуация, RT (раздельно вверх/вниз), Snap Tap (пара A/D,
  переключатель Fn+LShift).
- **Настройка**: слои Стандарт / Hypershift; игровой режим (блок Win, Menu,
  Alt+Tab, Alt+F4, «только в игре»); WASD → стик геймпада, Q/E → триггеры;
  режим печати (Fn+Ctrl+Esc → профиль по умолчанию).
- **Подсветка**: яркость, гашение при выключенном дисплее / простое.
- **Макросы**: задержка, клавиша, мышь, вложенный макрос, запуск программы,
  команда, текст, цикл.

## Linux

HID — `/dev/hidraw*` + udev-правило (конфликт с openrazer, если установлен);
перехват — `evdev` + `EVIOCGRAB`, эмуляция — `uinput`. LampArray нет — подсветка
только через `0F:xx`.
