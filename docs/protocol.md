# Протокол Huntsman V2 Analog

Проверено на живом устройстве (`1532:0266`, прошивка 1.06 — та же, что разобрана) или прочитано из кода Synapse 4 и
прошивки 1.06 ([firmware.md](firmware.md)). В разделе «Команды по прошивке» по
умолчанию не проверено; в остальных разделах непроверенное помечено.

## HID-интерфейсы

| Интерфейс | Usage page / usage | Назначение |
|---|---|---|
| MI_00 | 0x01 / 0x06 | Обычная клавиатура (boot), ОС захватывает монопольно |
| MI_00 Col02 | 0x01 / 0x04 | Режим геймпада (output-репорт 521 байт) |
| MI_00 Col03 | 0x0C / 0x01 | Consumer / system control |
| MI_01 Col01 | 0x01 / 0x06 | NKRO-клавиатура |
| MI_01 Col04 | vendor | Razer-коды в driver mode: `04 <code>`, `04 00` — отпущено |
| MI_01 Col06 | vendor | Поток глубины в driver mode, report `07` |
| MI_02 | 0x01 / 0x02 | Мышь (макросы; колесо громкости в driver mode) |
| **MI_03** | 0x0C / 0x01 | **Управление**: feature report 91 байт |
| MI_04 Col01 | 0x59 / 0x01 | HID LampArray (Windows Dynamic Lighting) |

## Пакет управления (MI_03)

Report ID `00` + 90 байт. CRC входящего пакета прошивка не проверяет.

```
0      status: запрос 00; ответ 02 ok, 01 busy, 03 fail, 04 timeout, 05 not supported
1      transaction id (устройство принимает любой; используем 1F)
2-3    remaining packets
4      protocol type (0)
5      data size — фактическая длина payload
6      command class
7      command id; get = set | 0x80
8-87   args[80]
88     crc = XOR байтов 2..87
89     reserved
```

Обмен: `SetFeature` → `GetFeature`. Прошивка принимает пакет только длиной ровно 90 байт
и выполняет команду сразу, в обработчике `SET_REPORT`; ответ готов к следующему
`GetFeature`. Статус `01` busy прошивка не возвращает, пауза 5–20 мс и повтор
нужны только на случай сбоя.

## Режим и профили

- `00:84` / `00:04` — режим: `00` hardware (клавиатура печатает сама), `03` driver
  (обычные нажатия не шлются, шлётся поток глубины). После включения — `00`.
  ⚠️ `01` — устройство пропадает и перечисляется как `1532:110E`; возвращается
  переподключением.
- `00:81` прошивка, `00:82` серийник.
- Esc + Caps Lock + Space при подключении включает и выключает демонстрационный
  режим (сохраняется): волна, реагирующая на глубину нажатия; команды `03` и `0F`
  в нём не действуют ([firmware.md](firmware.md#режимы-устройства)).
- `05:84` активный профиль (`01`), `05:81` список (`01 01`), `05:8A` → `05` (максимум профилей).
- **Профиль 0 — рабочая копия в RAM**: при включении заполняется из сохранённого,
  запись в него не трогает flash, после переподключения теряется. Запись Normal в
  профиль 0 меняет и Hypershift в профиле 0; в профиле 1 слои раздельные.
- **Смена режима (`00:04`) тоже перезаписывает профиль 0 из активного**: после
  переключения driver ↔ hardware временные назначения и эффект пропадают (проверено).
  Временные изменения после включения и выключения RT нужно отправить заново.

## Срабатывание

Отдельных команд актуации и RT у V2 нет, порог хранится в назначении клавиши:

- `02:92` get `[profile, fwID, layer]` (layer 0 — Normal, 1 — Hypershift), size 80.
- Ответ: `[profile, fwID, layer, thrL, thrH, fnId, fnSize, fnData…]`.
  Пример для клавиши A: `01 1F 00 00 00 02 02 00 04` — fnId `02` клавиша, `00 04` модификатор + HID usage.
- `02:12` set — тот же формат. В профиле ≥1 пишет во flash.
- `мм = thr/255·2.1 + 1.5`.
- `thrL` — точка нажатия, прошивка зажимает её в `15..250`. `thrH` — точка
  отпускания: не меньше `5` и не больше `thrL − 10`. Поэтому `0/0` даёт нажатие на
  15 и отпускание на 5, а `0/230` — то же самое. В hardware mode точка нажатия не
  бывает ближе 1.62 мм и дальше 3.56 мм. Проверено: с `thrL = 250` клавиша
  срабатывает только почти у дна.
- Synapse пишет всем клавишам `0/0` и в driver mode сам определяет срабатывание.
- **В driver mode профиль 0 принимает только пороги**: смену fnId прошивка молча
  отбрасывает (ответ ok). В hardware mode в профиль 0 пишется всё.
- `02:0D` / `02:8D` — то же назначение без порогов: `[profile, fwID, layer, fnId,
  fnSize, fnData…]`.

fnId — по обработчику нажатий прошивки. `02:0D` и `02:0F` проверяют fnId и длину
данных и при ошибке отвечают `03`; `02:12` пишет назначение без проверки.

| fnId | Данные | Действие |
|---|---|---|
| `00` | любые | выключено |
| `01` | `btn` | мышь: `01`–`08` кнопки, `09` / `0A` колесо вверх / вниз (проверено `03`, `0A`) |
| `02` | `mod usage` | клавиша |
| `03` | `id16 n` | макрос n раз; нажатие во время проигрывания игнорируется |
| `04` | `id16` | макрос по кругу, пока клавиша нажата; после отпускания доигрывается текущий проход |
| `05` | `id16` | макрос по кругу до повторного нажатия, так же доигрывает проход |
| `06` | 1, 2 или 5 байт по `data[0]` | принимается, при нажатии ничего не делает |
| `07` | `mode n` | профиль: `01` / `02` следующий / предыдущий, `04` / `05` то же по кругу, `03 n` — профиль n |
| `08` | 1 байт | принимается, при нажатии ничего не делает |
| `09` | `code` | system control: `81` power, `82` sleep, `83` wake; заводское Fn+Pause — `82` |
| `0A` | `usage16` | consumer (media) |
| `0B` | `btn` | двойной щелчок кнопкой мыши (проверено) |
| `0C` | `on` | Hypershift, пока клавиша нажата |
| `0D` | `mod usage rate16` | turbo клавиши (проверено `00 04 00 32`) |
| `0E` | `btn rate16` | turbo кнопки мыши |
| `0F` | `id16` | пошаговый макрос: каждое нажатие проигрывает следующие 2 события |
| `11` | `fn` | служебные, по заводским назначениям: `01` Fn, `03` игровой режим (Fn+F10), `04` Fn+F9 — мигает индикатор M ~1 с, `09` / `08` яркость − / + (Fn+F11 / F12); остальные — Razer-код хосту |

`10` и `12`+ проверка не пропускает. В driver mode прошивка сама обрабатывает только
`0C` (Hypershift) и `11 01` (Fn) из слоя Hypershift; остальное делает хост. В профиль 0 проверены на
запись `00`, `02`, `03`, `04`, `05`, `0A`, `0F`. Заводское Fn+Menu — `07 04`, следующий
профиль по кругу. Записи макроса на лету в прошивке нет: Fn+F9 только мигает M.

`fwID` — позиционные коды AT-101 (`~`=1, `Q`=17, `A`=31, Space=61), таблица —
`crates/core/src/keymap.rs`.

Не поддерживаются (`05`): `02:99`, `02:9A` (V3 multi-actuation и RT), `02:9F`,
`02:A0`, `02:A7`–`02:AA`. Для V3: `FW = мм·1638`, 16 бит BE.

## Поток глубины (driver mode)

- MI_01 Col06, report `07 (fwID depth)… 00`; пустой отчёт — всё отпущено.
- ~1 кГц, только при изменении, до 11 клавиш в отчёте, шум ±1–2. Глубина — среднее
  8 из 10 последних отсчётов без максимума и минимума.
- Глубина 0..255 = 1.5..3.6 мм — та же шкала, что у порога; 12 ед. = 0.1 мм.
- Нужен гистерезис отпускания ≥ 12 ед., иначе клавиша у порога дребезжит.
- `SendInput` не даёт автоповтора — хост повторяет сам.
- Fn-слой и медиа — на хосте: Col04 `04 52..55` — четыре медиа-клавиши, `04 01` — Fn.
- Колесо громкости приходит как колесо мыши (MI_02). Synapse переназначает его на
  VolumeUp/Down, вероятно, своим фильтр-драйвером.
- `02:2A` (report mode) не поддерживается (`05`); в hardware mode поток не идёт.

Synapse на V2 делает RT и Snap Tap на хосте: `profile.appEngine = {mappings,
actuations[{keyId, make, break}], rapidTriggers{fwID: {makeSensitivity,
breakSensitivity}}}` отдаётся в `mapping_engine.dll` (report `07`, `SendInput`,
опционально фильтр-драйвер). Аппаратного RT нет.

## Подсветка

### Эффекты `0F:02`

Аргументы `profile led effect…`, `led` = `05`. `profile` `00` — рабочая копия в RAM,
`01`–`05` — профиль во flash (после переподключения возвращается эффект активного
профиля). Чтение `0F:82 profile 05`.

| Эффект | Байты после `profile 05` |
|---|---|
| выключено | `00 00 00 00` |
| статичный | `01 00 00 01 RGB` |
| дыхание 1 / 2 / случайное | `02 01 00 01 RGB` / `02 02 00 02 RGB RGB` / `02 00 00 00` |
| спектр | `03 00 00 00` |
| волна | `04 dir speed 00`, dir `01`/`02`, чем меньше speed, тем быстрее |
| отклик: клавиша | `05 00 speed 01 RGB` (скорость не работает) |
| отклик: рябь | `06 00 speed 01 RGB` |
| звёздное небо | `07 00 speed 00` / `… 01 RGB` / `… 02 RGB RGB`, speed 1–3 |
| своя раскладка | `08 00 00 00` |
| пламя | `09 00 00 00` — в Synapse и в списке `0F:81` его нет (проверено). Параметров нет: остальные байты прошивка не читает, скорость и палитра фиксированы |

Яркость — `0F:04 profile 05 VV`, чтение `0F:84`. Два цвета у отклика не работают.

### Своя раскладка `0F:03`

- `00 led row start stop RGB×n`, size `5+3n`, `led` — `00` или `05` (байт `00` в начале
  прошивка не читает); сетка 8×23 (ряды 0–7, столбцы 0–22).
  Показ — `0F:02 00 05 08 00 00 00`.
- **Только в RAM**: эффект `08` в профиль ≥ `01` прошивка не сохраняет,
  хотя отвечает ok.
- Ряд 0 — F-ряд (медиа-кнопки — одна ячейка 18, колёсико — 21), 1–5 — клавиши,
  6 — подсветка по краю корпуса, 7 — подставка. Столбцы клавиш — `crates/core/src/layout.rs`.

### LampArray и Dynamic Lighting

- MI_04 Col01: 148 ламп (107 клавиш, 40 accent, 1 логотип), 30 кадров/с. По
  прошивке на других раскладках ламп 149 или 153.
  Feature-репорты: `1` атрибуты, `2`/`3` лампа, `4` multi-update, `5` range-update,
  `6` AutonomousMode.
- Запись ламп с хоста (репорты `4`, `5`) переключает эффект на `08` «своя раскладка».
  После `0F:10 01` прошивка эти записи игнорирует (проверено).
- **`AutonomousMode = 0`** — лампами управляет хост, `0F:02` не действует.
  `0 → 1` включает эффект по умолчанию из settings (спектр, `03`), а не эффект
  профиля — эффект надо отправить заново.
- Feature-репорт `7` на этом же интерфейсе — второй вход в канал управления:
  пакет в том же формате уходит тому же диспетчеру (на железе не проверено).
- DL со статичным цветом пишет один раз; с анимацией шлёт кадры непрерывно.
- Включение DL: `HKCU\Software\Microsoft\Lighting\AmbientLightingEnabled` (DWORD),
  служба применяет изменение сразу.

## Макросы

Тело макроса лежит в общем хранилище под своим id и не связано с клавишами;
клавиша ссылается на него назначением `02:12` с fnId `03`–`05`, `0F`. Прошивка
проигрывает макрос только в hardware mode.

- `06:08` `id16 size32` — выделить место. `06:09` `id16 offset32 len data…` —
  данные, до 72 байт за пакет. Читается `06:89` тем же форматом. Прошивка копит
  `06:09` в буфере и пишет во flash через 100 мс после последнего пакета, поэтому
  `06:89` сразу после записи может вернуть старые данные. `06:0D` (имя в
  Synapse) у V2 нет; имена храним на хосте.
- **Тело пишется только во flash**, варианта в RAM нет; в RAM может быть
  только привязка (профиль 0). Хранилище — встроенная flash `0x08090000`–`0x080FFFFF`;
  прошивка читает события прямо оттуда при проигрывании и только из этого
  диапазона ([firmware.md](firmware.md)).
- `06:80` количество, `06:81` / `06:8B` список id, `06:88 id16` размер, `06:03 id16`
  удалить.
- `06:8E` память: `FFFF, всего32, maxFree32, 0` — полезный объём всех блоков и
  самый большой свободный блок, оба посчитаны при подключении. На пустой клавиатуре
  `6FFF0` и `6FA78` (457 336 байт).
- `06:86` считает заново при каждом запросе: `count16, 0000, maxFree32, free32` —
  число макросов, самый большой свободный блок и всё свободное место. Проверено:
  после записи 4-байтного макроса `06:86` сразу показал `6FA60`, `06:8E` — старое
  `6FA78`. Для UI удобнее, чем `06:8E`.
- Макрос из `d` байт занимает блок `8 + ceil8(d + 6)`: 8 байт — метки блока, 6 —
  заголовок тела. Проверено на d = 2, 3, 12, 73.
- Удаление освобождает блок сразу и сливает его с соседними свободными; место можно
  занять сразу. Только `06:8E` показывает старые значения до переподключения.
- Индекс макросов — 100 записей по 14 байт, при переполнении растёт на 50;
  отдельного лимита на число макросов нет.
- `06:0A 00 00 00 02` — форматирование: удаляет все макросы, ответ `00 00 02 02`,
  свободное место возвращается сразу (проверено). `06:0A` с аргументами, которые шлёт
  Synapse, отвечает `05`.
- Одновременно играют до 20 макросов. Задержка между событиями по умолчанию —
  `06:07` / `06:87` (`01`), в интервалах опроса.
- ⚠️ Каждая запись во flash перезаписывает страницу 4 КБ целиком: частая запись
  изнашивает flash.

События, 2–5 байт:

| Байты | Событие |
|---|---|
| `01 usage` / `02 usage` | клавиша нажата / отпущена (HID usage) |
| `03`/`04`, `05`/`06` | power / media нажата / отпущена |
| `08 mask` | кнопки мыши |
| `0A 01` / `0A FF` | колесо вверх / вниз |
| `11 t8`, `12 t16`, `13 t24`, `14 t32` | задержка, BE, в интервалах опроса (при 1000 Гц — мс) |
| `15 x16 y16` | перемещение курсора |

Пример: `01 04 11 32 02 04 01 05 11 32 02 05` печатает `ab`.

## Команды по прошивке

Полный список из обработчиков прошивки 1.06 ([firmware.md](firmware.md)). Если не
сказано «проверено», на железе не проверялось. ⚠️ — пишет во flash то, что
Synapse не трогает; не отправлять.

### `00` — устройство

| cmd | Аргументы и смысл |
|---|---|
| `00:81` / `00:87` | версия прошивки, 2 / 4 байта: `01 06`, `01 06 00 00` (проверено) |
| `00:02` / `00:82` | серийник, 22 байта; ⚠️ `02` перезаписывает его |
| `00:83` | всегда `00 60` |
| `00:04` / `00:84` | режим: `00` hardware, `02` заводской, `03` driver, `01` — перезагрузка в загрузчик (проверено `00`, `01`, `03`). Режим `08` в коде есть, но в этой версии не работает |
| `00:05` / `00:85` | интервал опроса, мс: допустимо `1`–`5`, `8`, `10` (`1` — 1000 Гц); другое — `03` (проверено `02`, `06`). Сохраняется во flash |
| `00:06` / `00:86` | два байта в config |
| `00:0B` | `00` — перезагрузка после записи всех данных, клавиатура возвращается через ~2.5 с (проверено); `01 00` — settings к заводским, ⚠️ `01 01` — ещё и config (калибровка, серийник) |
| `00:3D` / `00:BD` | `idx(0/1)` + 14 байт в config. `00:BD 01` → `07E7 0005 0016 000A 0029 001E` — вероятно, дата производства (2023-05-22 10:41:30), `00` — нули |
| `00:B5 03` / `00:B9` | байт из `0x20000000` |

### `02` — клавиши

`profile` `00` — рабочая копия в RAM, `01`–`05` — flash; запись в активный
профиль копируется и в `00`.

| cmd | Аргументы |
|---|---|
| `02:02` / `02:82` | 4 байта в settings |
| `02:03` / `02:83` | `profile fwID fnId size data` — назначение без слоя |
| `02:0D` / `02:8D` | `profile fwID layer fnId size data` (проверено) |
| `02:12` / `02:92` | `profile fwID layer thrL thrH fnId size data` (проверено) |
| `02:11` / `02:91` | только пороги: `profile fwID _ thrL thrH` |
| `02:0F` | пакетно: `profile layer`, затем записи по 8 байт `fwID fnId size data[5]` |
| `02:8F` | `profile layer startFwID` → до 9 записей по 8 байт |
| `02:13` / `02:93` | `first last` + по 2 байта на клавишу (из 3 в settings), общие для всех профилей; смысл неизвестен |
| `02:07` / `02:87` | `profile flag` — флаг профиля, при смене сбрасывает нажатые клавиши; смысл неизвестен |

### `03` — индикаторы

LED: `07` — индикатор M, `08` — индикатор игрового режима (прицел), оба одноцветные;
`18` — RGB. Список — `03:89` → `03 07 01 08 01 18 03`. Проверено: `08` работает в
любом режиме; `07` слушается `03:00`/`03:02`/`03:04` только в driver mode, в hardware
mode M зажигает только Fn+F9.

| cmd | Аргументы |
|---|---|
| `03:00` / `03:80` | `00 led on` — вкл/выкл |
| `03:01` / `03:81` | `00 18 RGB` — цвет |
| `03:02` / `03:82` | `00 07 mode`: `0` — горит, `1` — мигает |
| `03:04` / `03:84` | `00 07 on off` — длительности мигания, по 100 мс; по умолчанию `05 05` |

### `05` — профили

`05:80` количество, `05:81` список, `05:84` активный, `05:8A` → `05` максимум,
`05:02` создать, `05:03` удалить, `05:04 id` сделать активным, `05:08` / `05:88`
`id off16 len16 data` — имя профиля в UTF-16BE (у профиля 1 — `default`, проверено),
`05:0B` — назначение не выяснено.

### `06` — макросы

К описанному в [«Макросах»](#макросы): `06:02 id` — создать запись в индексе, `06:04` /
`06:84` `id n` + `n` слов, `06:07` / `06:87` — задержка между событиями,
`06:0A` / `06:8A` `id x n` (`n = 2` — форматирование), `06:0C` / `06:8C` `id off16 total16 data` —
блоб макроса (вероятно, имя), `06:8B off` — список id постранично. `06:85`,
`06:8D` → `05`.

### `0F` — подсветка

| cmd | Аргументы |
|---|---|
| `0F:80` | `05 19 03 0B 17` — возможности; `17` = 23 столбца |
| `0F:81` | `led` (`00`/`05`) → эффекты `01`–`08` |
| `0F:02` / `0F:82` | `profile led effect p1 p2 n RGB×n`, `n ≤ 10` (проверено) |
| `0F:03` | `00 led row start stop RGB×n` (проверено) |
| `0F:04` / `0F:84` | `profile led VV` — яркость (проверено) |
| `0F:06` / `0F:86` | `profile flag` |
| `0F:10` / `0F:90` | `01` — прошивка игнорирует запись ламп через LampArray; эффект `08` при этом сменяется эффектом по умолчанию (проверено). Сохраняется во flash |

### `FE` / `F0` — заводской режим

Работают только в режиме устройства `02` (`00:04 02`), иначе `05`. `A7`, `A8`, `28`
требуют включённой калибровки (`FE:20 01`), иначе `03`. Всё, кроме `FE:28` и `FE:83`,
проверено; режим `02` сбрасывается `00:04 00` или переподключением.

| cmd | Аргументы |
|---|---|
| `FE:20` / `FE:A0` | включить / прочитать режим калибровки |
| `FE:A1` | `80`, если калибровка включена |
| `FE:A7` | записи `fwID 00 00` → сырое 16-битное значение датчика каждой клавиши, BE. При нажатии значение падает: Q в покое ≈ `0E53`, до упора ≈ `0240`; шум ~20 |
| `FE:A8` | `fwID 00 00 00 00` → пара калибровки, 2 × u16 BE: Q `0448 0D0F`, A `03E6 0D0F`. Вероятно, дно хода (глубина 255) и начало (глубина 0, общее для клавиш). Больше одной записи за запрос — `03` |
| `FE:28` | ⚠️ запись пар калибровки и сохранение во flash |
| `FE:83` | `ch < 8` — тест мультиплексора датчиков |

## Что ещё умеет Synapse для этой модели

По экранам Synapse 4 — ориентир для дорожной карты:

- **Срабатывание**: актуация, RT (раздельно вверх/вниз), Snap Tap (пара A/D,
  переключатель Fn+LShift).
- **Настройка**: слои Стандарт / Hypershift; игровой режим (блок Win, Menu,
  Alt+Tab, Alt+F4, «только в игре»); WASD → стик геймпада, Q/E → триггеры;
  режим печати (Fn+Ctrl+Esc → профиль по умолчанию).
- **Подсветка**: яркость, гашение при выключенном дисплее / простое.
- **Макросы**: задержка, клавиша, мышь, вложенный макрос, запуск программы,
  команда, текст, цикл.

## Команды Synapse, которых у V2 нет

В таблицах Synapse есть команды для других моделей. В прошивке V2 обработчиков
нет, ответ — `05`: `02:1B` Mod-Tap, `02:1E`, `02:27` / `02:2C` Snap Tap, `02:28`,
`02:29`, `02:2D`, `02:2E`, `02:31`, `02:33`–`02:37`, `02:B2` keymap'ы, `02:A4`,
`02:A8`, `02:9C`, `FE:2D`, `FE:AD`, `FE:AE`, `00:08`, `00:5A`, `00:5D`, `05:05`–`05:07`,
`05:09`, `05:0A`, `05:0C`. Snap Tap, игровой режим и RT на V2 — только на хосте; прошивка лишь переключает
индикатор игрового режима (`11 03`).

## Не проверено на железе

Остальное из этого файла, помеченное «проверено», подтверждено на устройстве. Здесь —
то, что известно только из прошивки.

Нужны нажатия:

- fnId `01` кнопки `04` / `05` — «назад» / «вперёд» (так считает EasyRazer), fnId `0A`
  — usage в BE (`00 E9` — громче), запись fnId в flash-профиль в driver mode;
- режимы проигрывания макроса: `03` игнорирует нажатие во время проигрывания, `04` и
  `05` доигрывают проход, `0F` проигрывает по 2 события; до 20 макросов одновременно;
- события макроса: мышь `08`, колесо `0A`, курсор `15`, media `05`/`06`;
- fnId `0E` (turbo мыши), `0C` (Hypershift), `11 03` (игровой режим), `07` (нужно ≥ 2
  профилей);
- точка отпускания `thrH` и нижний предел нажатия 15;
- перевод сырого значения датчика в глубину: `FE:A7` против потока глубины при одном
  нажатии;
- частота отчётов при `00:05` ≠ `01`;
- демонстрационный режим от зарядки, без компьютера.

Нужна доработка `razer-probe`:

- feature-репорт `7` на MI_04 как вход в канал управления;
- задержка записи `06:09` во flash — запись и чтение `06:89` в одном процессе.

Смысл не выяснен: `00:06`, `00:83`, блок `00:3D` / `00:BD 00`, `02:07`, `02:13`,
`05:0B`, `0F:06`, fnId `06` и `08`.

Не проверяем: `00:02`, `00:0B 01 xx`, `FE:28`, `FE:83`, режим `01`, fnId `09` и
события `03`/`04` (power, sleep). Проверить нельзя: раскладки на 149 и 153 лампы
(нужна другая клавиатура), загрузчик (нет в образе).
