# Прошивка Huntsman V3 Pro

Разбор официального Firmware Updater `v1.03.00_r1` (прошивка `1.03.00`, та же,
что Synapse называет `1.3.0.0`). Это справка для протокола: код прошивки в
проект не переносим. Адреса указаны для этой версии. Выводы без прямой проверки
помечены «вероятно». Команды — в [protocol.md](protocol.md).

## Образ

Updater тот же, что у V2 (.NET, распаковывается 7-Zip), параметры в
`DeviceUpdater.resources`:

| Ключ | Значение |
|---|---|
| `VID` / `PID` | `1532` / `02A6` |
| `BLPID` / `BLVER` | `110E` / `2.0` — загрузчик, как у V2 |
| `DevFWVer` / `FlashFWVer` | `1.03.00` / `1.03.00` |
| `FeatureReportLen` | `91` |
| `RYFWFileName` | `Talia_T1_7203_App_FW_20240426_v1.3.0_0D55D9FF.enc` |

Образов два:

- `DevFWLine0..8292` — Intel HEX главного MCU, открытый: `0x20000000`–`0x200205FF`,
  132 608 байт.
- `FlashFWSector0..36` — 37 408 байт, зашифрованы (энтропия ~6.2 бит/байт),
  прошиваются через `Ry_Online_Update_Dll`. Вероятно, это второй чип; для
  протокола не понадобился. `update/update_config.ini` ссылается на PID `02B0` и
  другой `.enc` — похоже, остался от V3 Pro Mini.

Разбор в Ghidra 12 headless: `ARM:LE:32:Cortex`, raw binary с базой
`0x20000000`, плюс неинициализированные блоки SRAMX `0x04000000`, RAM
`0x20020600`, периферии `0x40000000` и SCS `0xE0000000`.

## Микроконтроллер

NXP, вероятно LPC55xx (Cortex-M33):

- строки NXP MCUXpresso SDK 2.8.2 (`fsl_gpio.c`, `fsl_spi.h`, `fsl_utick.c`),
  девять FLEXCOMM, CTIMER, UTICK, WWDT, GINT;
- стек — `0x04008000`, конец 32 КБ SRAMX; reset — `0x20000215`;
- код слинкован в RAM, а не во flash: его, вероятно, копирует туда загрузчик.

Инициализированные данные сжаты (как у V2, под Keil): VID/PID и HID-дескрипторы
видны в `0x2001FB09` только фрагментами.

## Канал управления

Пакет — `0x2002AF38`: status `+0`, size `+5` (`0x2002AF3D`), class `+6`, id `+7`,
args с `0x2002AF40`. Ответ пишется в тот же буфер.

| Адрес | Что |
|---|---|
| `0x200125A0` | диспетчер классов |
| `0x2001189C` | `00` |
| `0x2000FB78` | `02` — клавиши, актуация, RT, Snap Tap |
| `0x20011BDC` | `03` |
| `0x20012654` | `05` |
| `0x20011F74` | `06` |
| `0x20011338` | `0A`, `0F` — подсветка |
| `0x200129A4` | остальные классы, в том числе `FE` |

## Профили

Профиль — `0x11B3` байт. Профиль 0 (рабочая копия) — в RAM, `0x200269A8`.
Профили 1–6 — во flash, `[0x20026314] + n·0x11B3`: команды читают и пишут их
прямо там (см. [«Запись во flash»](#запись-во-flash)). Номер больше 6 команды
отвергают. Активный профиль — `0x20029002`.

| Смещение | Поле |
|---|---|
| `+0x979` | уровень актуации (см. ниже) |
| `+0x980` | пороги: 135 × 7 байт `fwID ? ? H:u16 L:u16` (LE в памяти) |
| `+0xD31` | RT включён |
| `+0xD32` | уровень RT |
| `+0xD33` | RT: 135 × 8 байт `fwID on on up:u16 down:u16 01` |
| `+0x116B` | continuous RT (`02:20`) |
| `+0x116C` | Snap Tap: `on fwID1 fwID2` (`02:21`) |
| `+0x116F` | флаг `02:07` |
| `+0x1172` | 4 байта `02:15` |
| `+0x11B1` | CRC-16/CCITT-FALSE (init `FFFF`, полином `1021`) по `+0`…`+0x11B0` |

Рабочие копии таблиц для текущего профиля: пороги — `0x20027328`, уровень —
`0x20027321`; RT — `0x200276DB`, флаг — `0x200276D9`, уровень — `0x200276DA`;
continuous RT — `0x20027B13`; Snap Tap — `0x20027B14`–`0x20027B16`. Режим
устройства (`00:04`) — `0x04000DE3`.

## Запись во flash

- `0x2000C430(addr, src, n)` — запись диапазона: страница 512 байт читается в
  `0x04001000`, меняется и перепрограммируется (`0x2000C39C`), до 3 повторов.
  Страница 512 байт — ещё один довод за LPC55xx.
- `0x2001A074` пересчитывает CRC профиля и пишет её той же функцией.
- Отложенного сохранения, как у V2, нет: команда в профиль 1–6 (`02:19`, `02:1A`,
  `02:20`, `02:21`, `02:07`, `02:15`) сразу стирает минимум две страницы —
  данные и CRC. Пачка на 15 клавиш стоит столько же, сколько одна клавиша, так
  что писать во flash надо крупными пачками, а живые изменения — в профиль 0.
- Где во flash лежат профили (значение `[0x20026314]`), не выяснено: указатель
  задаётся в сжатых данных.

## Срабатывание

- Пороги и RT — u16, 1638 = 0.1 мм. Таблица уровней актуации `0x2001B3DE`:
  `1638·{1, 4, 8, 12, …, 36}` (0.1, 0.4, 0.8 … 3.6 мм); RT — `0x2001E11E`:
  `1638·{1…10}` (0.1…1.0 мм).
- При записи всех клавиш (`fwID = FF`) прошивка ставит «уровень» профиля —
  наибольший номер ступени, не превышающий L первой клавиши (для RT — down).
  Зачем он, не выяснено; вероятно, для индикации.
- Старые `02:12` / `02:92` работают со старшим байтом u16.

## Snap Tap

Обработка события клавиши (`0x2000DA74`, перед движком нажатий): если `02:21`
включён и режим не `03`, нажатие клавиши пары отпускает вторую, отпускание —
снова нажимает вторую, если она удерживается. Состояние пары — `0x200283CC`–
`0x200283CE` и `0x040019C8`–`0x040019CA`.

## Не разобрано

- Карта flash, ресурс страницы, хранение config, settings и макросов.
- Опрос датчиков и решение о нажатии, driver mode и поток глубины.
- USB и HID-дескрипторы (распаковка сжатых данных).
- Байты `+1`, `+2` записи порогов, эффект `0A`, флаг `02:1F`.
- Второй образ (`.enc`).
