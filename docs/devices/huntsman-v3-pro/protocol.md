# Протокол Huntsman V3 Pro

На железе не проверено. Источники: модуль Synapse 4 для `678` (`1532:02A6`) и
обработчики прошивки 1.03.00 ([firmware.md](firmware.md)). Где они расходятся или
источник один — помечено. Формат пакета — [в обзоре](../README.md#пакет-управления).

## Устройство

- Канал управления — интерфейс 3, feature report 91 байт (Synapse:
  `claimInterface: 3`; updater: `FeatureReportLen = 91`).
- Режим `00:04` / `00:84`: `00` hardware, `03` driver, `01` — флаг, вероятно, вход
  в загрузчик, как у V2. При переходе в driver mode прошивка делает активным
  профиль 1. В driver mode отключён Snap Tap (`02:21`).
- Профили: `0` — рабочая копия в RAM, `1`–`6` — сохраняемые. Synapse использует 5
  слотов (`OBMSlots: 5`), имена профилей хранит в прошивке, включая первый.
- Поток аналоговых данных — report `0B` (Synapse: `analogKeyboardV2ReportID`;
  у V2 — `07`). По прошивке не проверено: HID-дескрипторы лежат в сжатых данных.

## Срабатывание

Порог — u16 **big-endian**, 1638 = 0.1 мм, `65520` = 4.0 мм. Так считает Synapse
(`unit: 1638`, `min: 1638`, `max: 65520`, по умолчанию `19656` = 1.2 мм,
`minBreak: 256`), и в прошивке ступени по 1638: актуация 0.1…3.6 мм, RT 0.1…1.0 мм.

Первый байт аргументов `02:19`, `02:1A`, `02:99`, `02:9A`, `02:9C` — **режим
значений**: `00` — u16, иначе 1 байт (это старший байт u16, младший — `00`).
Synapse всегда шлёт `00`.

| Команда | Аргументы |
|---|---|
| `02:19` set актуация | `mode profile {fwID H:u16 L:u16}×≤15` |
| `02:99` get | `mode profile fwID×≤15`, ответ — тот же формат, что у set |
| `02:1A` set RT | `mode profile {fwID on up:u16 down:u16}×≤13` |
| `02:9A` get | `mode profile fwID×≤13`, ответ как у set |
| `02:20` / `02:A0` | continuous RT: `profile on` / `profile` → `profile on` |
| `02:9C` | `mode {fwID value:u16}…` — значение датчика клавиши (Synapse: Get Multi Analog Key ADC Data) |

- `fwID = FF` — все клавиши сразу; `00` — ошибка `03`.
- H и L — как у V2: L — нажатие, H — отпускание (порядок в пакете — H, потом L).
- В `02:1A` нулевые up или down не меняют сохранённое значение. `on = 01` хотя бы у
  одной клавиши включает RT профиля целиком.
- Профиль `0` меняет только RAM; `1`–`6` пишутся в профиль и, если он активный,
  применяются сразу.

Старые `02:12` / `02:92` (формат как у V2: `profile fwID layer thrL thrH fnId
fnSize fnData…`) работают, но порог в них — старший байт u16, то есть
`0..255` ↔ 0–4 мм с шагом ≈ 0.016 мм, а не 1.5–3.6 мм, как у V2.

## Snap Tap

`02:21` — `profile on fwID1 fwID2`, одна пара клавиш; `02:A1` — `profile` →
`profile on fwID1 fwID2`. В Synapse называется kill switch (`killSwitch`).

По прошивке: нажатие одной клавиши пары отпускает другую; при её отпускании
удерживаемая вторая снова нажимается. Только в hardware mode. `02:27` (Snap Tap
Ctrl из таблицы Synapse) обработчика нет.

## Назначения клавиш

- `02:0D` / `02:8D` — как у V2: `profile fwID layer fnId fnSize fnData…`.
- `02:1E` set / `02:9E` get — пачкой: `profile {fwID layer fnId fnSize data[5]}…`,
  по 9 байт на клавишу. Synapse читает назначения через `02:9E` по 8 клавиш.
- `02:12` / `02:92` — назначение вместе с порогом, см. выше.

## Подсветка

Класс `0F` совпадает с V2: `0F:02` эффект (LED `05`; `00` прошивка подменяет на
`05`), `0F:03` своя раскладка (`store led row first last RGB…`, LED `05` или `00`),
`0F:04` / `0F:84` яркость, `0F:82` эффект.
Эффекты `00`–`0A`: на один больше, чем у V2 (`09` — пламя), что такое `0A` —
не выяснено.

## Команды класса `02` по прошивке

Set: `02`, `03`, `07`, `0D`, `0F`, `11`, `12`, `13`, `15`, `19`, `1A`, `1E`, `1F`,
`20`, `21`. Get: `82`, `83`, `87`, `8D`, `8F`, `91`, `92`, `93`, `95`, `99`, `9A`,
`9C`, `9E`, `9F`, `A0`, `A1`. Остальное — `05`.

`02:1F` / `02:9F` — один флаг (Synapse: Analog Key Adjustment Mode Ctrl), что он
меняет, не выяснено.
